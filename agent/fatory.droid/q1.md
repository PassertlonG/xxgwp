## 项目概述
- **项目名称**：多端销售管理系统
- **业务定位**：连接厂家、经销商和终端客户的综合销售平台
- **涉及端**：
    - 客户端：微信小程序（B2C）
    - 经销商端：微信小程序 + 安卓 App + 网页（B2B）
    - 厂家端：网页后台管理
    - 后端：统一 API 服务，为以上所有端提供数据和业务逻辑支撑

## 技术栈与工具链
- **前端跨端方案**：Taro 4.x (React + TypeScript)，一套代码同时编译到微信小程序和 H5（网页），安卓 App 通过 Taro H5 打包或 Tauri 2.0 壳实现
- **后端框架**：Rust 的 Axum（Tokio 异步生态），使用 SeaORM 操作 PostgreSQL
- **数据库与缓存**：PostgreSQL (主数据库) + Redis (缓存及轻量消息队列)
- **容器化**：全服务 Docker 化，使用 docker-compose 编排
- **代码检查**：Rust 使用 Clippy，前端使用 ESLint + TypeScript ESLint

## 功能模块需求（初步细化）
1. **用户与认证模块**：统一登录/注册（支持微信授权、账号密码）、角色管理（厂家、经销商、客户）、JWT 鉴权
2. **厂家后台模块**：商品管理（多规格 SKU）、经销商管理、价格策略、库存查看、订单管理、统计报表
3. **经销商端模块**：商品选购、快速下单、客户管理、订单跟踪、销售数据看板
4. **客户端模块**：商品浏览、购物车、下单、支付（模拟/集成）、订单物流追踪、个人中心
5. **订单与交易模块**：订单状态机、库存扣减、支付回调、退款流程
6. **通知与消息模块**：站内信、消息推送（WebSocket）、订单状态变更通知
7. **系统基础能力**：API 路由统一管理、错误处理、日志、配置管理、数据验证

## 架构与非功能要求

- **代码质量**：所有生成代码必须通过 Clippy 和 ESLint 检查，无警告
- **测试要求**：每个模块需包含单元测试和集成测试，测试通过后方可提交
- **文档**：生成的 API 接口需要有 OpenAPI 文档注释，核心业务逻辑需要简要说明
