# 软件需求规格说明书(一期)

## 湘西果王油商城系统

---

## 1. 项目概述

### 1.1 项目背景

湘西果王油是一款面向重视健康的中产家庭的健康食品（食品类别销售）。本项目旨在开发一套支持自营电商及多级分销体系的小程序商城系统，帮助厂家完成商品展示、在线交易、订单管理、分销结算等核心业务流程。

### 1.2 项目目标

开发一套基于微信小程序的电商系统，第一期实现完整的交易闭环，后续分期逐步上线内容运营、分销裂变、佣金体系、统计报表等功能。

### 1.3 项目分期

| 分期 | 主题 | 目标 |
|:---|:---|:---|
| 第一期 | 交易闭环 | 单人完成浏览→下单→支付→发货→收货全流程 |
| 第二期 | 内容运营 + 分销基础 | Banner/公告管理、分享裂变、关系绑定 |
| 第三期 | 完整分销体系 | 等级晋升、佣金引擎、提现审核 |
| 第四期 | 统计与增强 | 报表、多支付方式记录、物流轨迹 |

## 2. 第一期需求详述 — 交易闭环

### 2.1 角色定义

| 角色 | 说明 | 访问端 |
|:---|:---|:---|
| 消费者 | 未购买过的浏览用户，可浏览、下单、支付 | 微信小程序 |
| 厂家/管理员 | 商品、订单、库存等后台管理操作 | H5 网页后端 |

> 注：第一期不实现分销商等级体系，所有已购买用户统称为"客户"，无前台等级区分。

### 2.2 总体规则

- **登录策略**：首次进入小程序无需登录，可浏览商品和分类。当访问需登录/授权的页面时，后端返回特定状态码，前端提示并引导用户进行微信授权登录。
- **支付渠道**：仅微信支付。
- **登录方式**：仅微信静默授权 + 手机号授权，不支持账号密码注册登录。
- **权限管控**：后端基于 Spring Security 做接口级权限校验，返回标准 HTTP 状态码与错误码，前端根据响应码控制页面跳转或展示登录引导。
- **软删除**：所有数据表均不执行物理 DELETE 操作，统一使用 `is_deleted BOOLEAN DEFAULT FALSE` 标记删除状态。删除操作仅将标记设为 true，数据保留以供后续审计和恢复。后期数据库维护时再批量清理已删除数据。

#### 2.5.2 业务流程

```
浏览商品 → 选择规格/数量 → 点击"立即购买"
    → 订单确认页（展示商品、数量、总价、优惠、地址）
    → 用户点击"去支付"
        → 系统创建订单，锁定相关 SKU 库存
        → 调用微信支付统一下单
        → 用户支付（微信支付弹窗）
        → 支付成功回调 → 订单状态变更为"已支付"
        → 管理员在后台发货 → 状态变更为"已发货"
        → 用户确认收货 → 状态变更为"已完成"
        → （可选）用户申请退款 → 管理员审核
```

**订单状态机**

```
待支付 → (30分钟超时自动取消) → 已取消
待支付 → 支付成功 → 已支付
已支付 → 发货 → 已发货
已发货 → 确认收货 → 已完成
已支付/已发货 → 申请退款 → 退款中
退款中 → 审核通过 → 已退款
退款中 → 审核拒绝 → 原状态恢复
```

#### 2.5.3 优惠规则：第二件打折

- 第一期仅支持一种优惠：同规格同商品的第二件折扣（百分比可配置，存储在系统参数表中）。
- 折扣计算逻辑：**不改 SKU 原价**，在订单确认页实时计算优惠总额，存入 `orders.discount_amount`。`order_items.price` 和 `order_items.subtotal` 始终快照 SKU 原价和原价小计，不受折扣影响。
- 例：SKU 原价 ¥100，第二件 8 折，用户购买 3 件：
  - `order_items.subtotal` = 3 × ¥100 = ¥300（原价小计）
  - `orders.discount_amount` = ¥20（仅第 2 件打折，¥100 × 20%）
  - `orders.pay_amount` = ¥280
- 优惠金额在订单确认页实时计算并展示。

#### 2.5.4 库存规则

- 订单创建（点击支付按钮时）即锁定对应 SKU 库存。
- 支付失败 / 订单超时未支付 → 库存回滚。

> **`POST /api/orders` 实现要点**：
> 1. 使用 Redis `DECR` 原子扣减 SKU 库存，扣减后若库存 < 0 则回滚（`INCR`）并返回 HTTP 409
> 2. 或使用 PostgreSQL `SELECT ... FOR UPDATE` 行级锁扣减库存
> 3. 扣减成功后才写入 `orders` + `order_items` 记录
> 4. 整个流程包裹在同一事务中，任一步失败则全部回滚（含 Redis 库存回滚）
> 5. 支付超时（30min）由定时任务扫描 `status=待支付` 且 `created_at < now()-30min` 的订单，批量取消并回滚库存

## 3. 非功能需求

### 3.1 库存超卖防护

- 订单创建时使用数据库行级锁或 Redis 原子操作扣减 SKU 库存。
- 扣减成功后才允许创建订单记录。
- 支付超时未支付或支付失败时，必须在事务中回滚库存。

### 3.2 支付幂等性

- 微信支付回调通知必须做幂等处理（以微信支付单号 + 订单号唯一索引防重）。
- 重复通知不重复更新订单状态。

### 3.3 超时取消

- 待支付订单 30 分钟未支付 → 系统自动取消并释放库存。
- 建议通过延时队列或定时任务实现。

### 3.4 数据安全

- 用户密码（如果有）必须 bcrypt 加密。
- 所有 API 需防 SQL 注入、XSS 攻击。
- 微信 openid、手机号等敏感字段需加密存储。
